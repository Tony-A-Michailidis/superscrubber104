# Rule reference

> Generated by `airlock rules --format md` from the rule catalogue. Do not edit by hand:
> a test compares this file with the catalogue.

airlock records 212 rules. Each finding names its rule, so this is what every line of a report means.

* **Severity** is the rule's own. **Default** is what a failing finding leads to under the built-in policy defaults: `block`, `require-approval`, `warn` or `allow`. A policy can change both, per rule and per path.
* **refuse (final)** marks the 42 integrity and authenticity rules. No policy, waiver or approval can change them: if they could be overridden, the airlock would not be a control.
* **Controls** are NIST SP 800-53 Rev 5 identifiers the finding is evidence for. A site can remap them (`controls.overrides`). airlock never marks a control satisfied: that is the assessor's call.
* A check that could not run is recorded under the same rule as *not assessed*, never left out.
